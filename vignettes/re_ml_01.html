3. Preprocessing

# We define the recipe and we select the numeric predictors 
gpp_recipe <- recipe(GPP ~ TA_F + SW_IN_F + LW_IN_F + VPD_F + P_F + WS_F, data = train_data) %>%
  # We apply Yeo-Johnson transformation to all numeric predictors (makes the distributions of the variables more normal-like). We use it over the Box-Cox because because Box-Cox requires strictly positive (> 0) values, and our data includes non-positive values in TA_F (negative) and P_F (zero)
  step_YeoJohnson(all_predictors()) %>%
  # We center all numeric predictors (subtract mean)
  step_center(all_predictors()) %>%
  # We scale all numeric predictors (divide by standard deviation)
  step_scale(all_predictors())

# Print the recipe

4.1. Liner regression model evaluation on test data

# We define a function to calculate metrics and create plots
eval_model <- function(model, test_data, model_name) {

  # We make predictions on the test data
  predictions <- predict(model, newdata = test_data)

  # We create a data holding observed and predicted values
  eval_data <- data.frame(
    Observed = test_data$GPP,
    Predicted = predictions
  )

  # We calculate performance metrics using the built-in functions from the yardstick package
  rmse <- yardstick::rmse_vec(eval_data$Observed, eval_data$Predicted)
  rsquared <- yardstick::rsq_vec(eval_data$Observed, eval_data$Predicted)
  mae <- yardstick::mae_vec(eval_data$Observed, eval_data$Predicted)

  cat(paste0(model_name, " Performance on test set:\n"))
  cat(paste0("RMSE: ", round(rmse, 3), "\n"))
  cat(paste0("R-squared: ", round(rsquared, 3), "\n"))
  cat(paste0("MAE: ", round(mae, 3), "\n\n"))

  # Create scatter plot
  p <- ggplot(eval_data, aes(x = Observed, y = Predicted)) +
    geom_point(alpha = 0.5) +
    geom_abline(intercept = 0, slope = 1, linetype = "dashed", color = "red", linewidth=1) + 
    labs(
      title = paste(model_name, ": Observed vs. Predicted GPP (test set)"),
      subtitle = paste("RMSE:", round(rmse, 3), " R²:", round(rsquared, 3), "MAE: ", round(mae, 3)),
      x = "Observed GPP",
      y = "Predicted GPP"
    ) +
    theme_minimal() +
    coord_fixed(ratio = 1) # This ensure axes have the same scale for 1:1 comparison

  print(p)
}

6. Results interpretation

Analyzing the evaluation between the training and the test set, we can observe some interesting results. The variance didn’t increase with the more complex KNN model compared to the simpler LM model. The R² drop was smaller for the KNN model and his value also higher:

  - LM: CV R² ≈ 0.698 --> Test R² ≈ 0.688 (Drop ≈ 0.010)
  
  - KNN (k=8): CV R² ≈ 0.729 --> Test R² ≈ 0.727 (Drop ≈ 0.002)

This means that the KNN model with k=8, despite being more flexible than the LM model,generalized well from the training data to the test data without significant overfitting.

The KNN model also had clearly better test set metrics (RMSE: 1.438 vs 1.537; R²: 0.727 vs 0.688). This means that it has a lower bias compared to the LM model. This also strongly suggests that the underlying relationship between the environmental predictors (temperature, radiation, VPD, etc.) and GPP is likely not strictly linear, so the the assumption of linearity of the LM model doesn’t fully capture the real-world complexity unlike the more flexible KNN model.

So in brief, the linear regression model is positioned more towards the high bias low variance end of the spectrum because of its rigid linear assumption preventing it from fitting the data perfectly. This inherent simplicity also means it’s less sensitive to noise in the training data, resulting in low variance, as evidenced by the small drop in performance from CV to test. The K-Nearest Neighbors model positioned more towards the lower bias end of the spectrum by being flexible enough to capture more of the true relationship. While more flexible models like KNN can be prone to higher variance, for this specific dataset and the choice of k=8 appears to have effectively managed this variance, leading to minimal overfitting, as shown by the very small drop in performance between CV and test results

Part 2: KNN tuning

1. Hypothesis

As k approaches 1, the training set MAE should be very low, potentially close to 0 (the model basically “memorize” the training data points) but the test set MAE should be high, potentially close to 1 (the model overfitted pattern doesn’t generalize well on new data). The training set R² should be very high, potentially close to 1 (the model explains almost all the variance of the memorized training data), conversely the test set R² should be low (the model doesn’t generalize well, it explains little of the variance in the new data).

As k approaches N, the training set MAE should be high (because it basically predict the average GPP, so predictions are poor for single individual training points) and the test set MAE should also be high. The training set R² should be close to 0 (predicting the mean cannot explain the variance around it). The same is true for the test set R².

So, somewhere in the middle we should find an optimal k that minimize the variance and the bias (low MAE and high R²).

2. Testing the hypothesis

  )

  # We make predictions on the training set
  train_preds_k <- predict(knn_model_k, newdata = train_data)

  # We calculate metrics for the training set
  train_mae_k <- mae_vec(truth = train_data$GPP, estimate = train_preds_k)
  train_rsq_k <- rsq_vec(truth = train_data$GPP, estimate = train_preds_k)

  test_preds_k <- predict(knn_model_k, newdata = test_data)

    k = k_val,

We can observe the overfitting region from the large discrepancy of performance between the training set and the test set. When the k value is low (e.g., k=1), we have excellent performance (extremely low MAE and extremely high R²) for the training set but very poor performance for the test set (low R² and high MAE). This indicates the model has learned the noise in the training data and doesn’t generalize.

We can also observe the underfitting region when using veri high k values. Beyond the optimal k range (approximately k=8 to k=25-30 in our plots), the performance metrics degrade on both the training and testing sets. As k becomes very large, the training data MAE continue to increase and the R² to decrease. This degradation is even more pronounced in the test set plot where for very high k values the MAE value increase and the R² value decrease even more rapidely. This signifies that the model has become too simple and cannot capture the underlying patterns in the data

2.1. K-MAE function

# We define the function
calculate_test_mae_for_k <- function(k_value, 
                                     recipe_obj, 
                                     training_data, 
                                     testing_data, 
                                     target_variable_name = "GPP") {knn_model <- train(x = recipe_obj, data = training_data, method = "knn", tuneGrid = data.frame(k = k_value), trControl = trainControl(method = "none"))
  
  # We make predictions on the testing set
  test_predictions <- predict(knn_model, newdata = testing_data)
  
  # We calculate MAE for the testing set
  test_mae <- mae_vec(truth = testing_data[[target_variable_name]], estimate = test_predictions)
  
  # Return the calculated MAE
  return(test_mae)
}
